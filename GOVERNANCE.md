# Governance

Android Open Project uses a maintainer-led governance model.

## Decisions

Routine catalog changes are accepted when they follow the published contribution and curation rules. The lead maintainer makes final decisions on scope, disputed classifications, automation, releases, security response, and maintainer access.

Substantial policy changes should be proposed in an issue or pull request so the reasoning remains public and reviewable. Decisions should favor verifiable technical value, project safety, accessibility, and long-term maintainability.

## Transparency

- Catalog policy is documented in `README.md` and `CONTRIBUTING.md`.
- Planned work is documented in `ROADMAP.md`.
- Material changes are recorded in `CHANGELOG.md` and Git history.
- Removed resources remain traceable in `docs/archived-links.md`.
- Security-sensitive reports follow `SECURITY.md` and may be handled privately.

## Conflicts of interest

Contributors should disclose when they recommend a project they own, maintain, or represent commercially. Disclosure does not disqualify a resource, but the same quality and relevance rules still apply.
